# 分支规范

受控工作区中的常规运行期工作直接写入默认分支。

以下情况**必须使用 `branch + PR`**：

- 流程更改；
- 政策更改；
- 仓库结构更改；
- 代码或脚本更改；
- 有风险或大体量的导入；
- 清理操作；
- 修改大量现有文件；
- 明确要求审阅。

不要为普通资料投递、回复工作包、消息、签退记录或 JSON 登记库记录创建分支。

如果当前工作区是公共/仅供参考工作区，对供分发的 LabNote 框架进行更改时，必须使用分支/PR 流程，而不是把这些更改当作常规投递处理。

未经操作者批准，不要删除分支。

除非操作者明确指示，否则不要强制推送（force-push）。
